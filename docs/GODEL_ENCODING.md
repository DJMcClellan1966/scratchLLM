# Gödel encoding of LLM encodings

We map scratchLLM’s discrete objects to **natural numbers** (Gödel-style) so we can refer to “statement n” or “sequence n” and, in principle, reason about the system at a meta level (e.g. limits, incompleteness).

## What is encoded

| Object | API | Description |
|--------|-----|-------------|
| Token ID sequence | `encode_token_sequence(ids)`, `decode_token_sequence(n)` | List of token indices from the BPE tokenizer. Empty list encodes as 1. |
| MeaningStruct | `encode_meaning(m)`, `decode_meaning(n)` | BE/QUERY/PRED dict from the meaning language. Canonical JSON (sorted keys) → UTF-8 bytes → prime-power encoding. |
| Statement | `encode_statement(s)`, `decode_statement(n)` | Truth-base statement. `to_dict()` → canonical JSON → bytes → prime-power encoding. |

## How encoding works

- **Prime-power encoding:** A sequence of non-negative integers `[v0, v1, ..., vk]` is mapped to  
  `2^(v0+1) * 3^(v1+1) * ... * prime(k)^(vk+1)`.  
  The `+1` makes 0 representable. Empty sequence → 1.
- **MeaningStruct / Statement:** First serialized to canonical JSON (sorted keys, no extra whitespace), then to UTF-8 bytes. The byte sequence (each byte 0–255) is encoded as above.

So every token sequence, meaning struct, or statement (in our schema) gets a unique natural number, and we can decode that number back to the object.

## What we might learn (meta-use)

- **“Statement n”:** We can say “the sentence with Gödel number n is in the truth base” or “the model generated the sequence with Gödel number m” by encoding the object and referring to its number.
- **Limit analysis:** If we defined a formal system over these numbers (e.g. “provable” = “generated by the model under rule R”), we could ask whether that system is strong enough for Gödel’s construction. Then we might prove that *some* true statements (in that system) are not “provable” by the model—a ceiling on what the model can do. We do **not** implement that formal system or proof here; we only provide the encoding.
- **Decidability:** With Gödel numbers we can ask: is “sequence n is in the support of the model” decidable? Is “struct n conflicts with struct m” decidable? Encoding is the first step toward formalizing such questions.

## What would be needed for an incompleteness-style argument

1. A **formal system**: axioms and inference rules that define “proof” (e.g. “the model generates step S given context C”).
2. **Consistency**: The set of “provable” statements does not contain both A and not-A. (LLMs can output contradictions; we’d need to restrict to a consistent fragment.)
3. **Sufficient strength**: The system can represent basic arithmetic (so Gödel’s self-referential sentence can be built).
4. **Recursive enumerability**: The set of Gödel numbers of provable statements is recursively enumerable.

We do not implement any of that—only the bijection between objects and numbers. The encoding is the first step; the rest is future work.

## Practical note

Prime encoding grows **exponentially** with sequence length. Keep token sequences and JSON payloads short (e.g. a few dozen tokens or a small meaning struct). For very long sequences, the Gödel number may be huge; decode still works (Python `int` is unbounded), but storage and comparison become expensive.
